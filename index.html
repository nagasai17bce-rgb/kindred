How Kindred works

This prototype uses deterministic demo logic. It does not call an external LLM or store real user data.

1. Conversation parsing
Demo rules identify common preference phrases. A production version would use an LLM with structured output.
2. Clarification
When a phrase is ambiguous, the prototype asks a follow-up question before updating a preference.
3. Profile update
The profile stores the current preference, confidence and whether you confirmed it.
4. Compatibility ranking
A weighted illustrative score compares your preferences to fictional candidate attributes.
5. Feedback loop
Your explicit feedback can update selected preferences. Real learning would require evaluation and consented outcome data.
Safety by design
Production matching should enforce age eligibility, consent, privacy, moderation and mutual interest.
